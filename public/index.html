Como funciona

[quem acessa]                         [relay]                      [computador acessado]
ssh -> 127.0.0.1:2222 -> connect  ==HTTPS/WebSocket==>  <==HTTPS/WebSocket==  serve -> 127.0.0.1:22 (sshd)

Os dois lados só fazem conexões de saída para este relay (HTTPS), por isso funciona atrás de NAT, CGNAT e firewall. O SSH continua criptografado de ponta a ponta: o relay só repassa bytes.

Problemas comuns
  • “nenhum computador online com id …”: o passo 2 não está rodando nesse computador, ou o id está diferente.
  • “serviço local 127.0.0.1:22 indisponível”: o servidor SSH não está instalado/ligado no computador acessado (passo 1).
  • “secret inválido”: o secret não confere com o TUNNEL_SECRET do relay.
  • “Acesso negado” no cmd: alguns antivírus bloqueiam powershell -Command "irm … | iex". Use os comandos desta página (aba cmd), que usam outra forma.
  • Aviso de chave do host mudou: o computador com esse id foi trocado/reinstalado. Remova a entrada antiga com ssh-keygen -R .
Segurança
  • Quem tem o secret consegue chegar até a tela de login do SSH, mas ainda precisa da senha (ou chave) do Windows.
  • Recomendado: usar login por chave SSH e desativar a senha (PasswordAuthentication no em C:\ProgramData\ssh\sshd_config).
  • Não coloque o secret na URL: ela fica registrada nos logs do proxy.
